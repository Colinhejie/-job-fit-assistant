# 真实宿主测试计划（未执行）

本文件是**给用户在有宿主环境时执行**的步骤。当前环境没有暴露任何浏览器工具，
因此第六节全部记为**未测试**；静态扫描"没有 HTTP 客户端"**不能**作为"不会外发"的充分证据。

## 0. 先确认宿主真实能力（不要虚构工具名）

在宿主对话里问自己 / 查看工具列表，记录实际存在的工具名与版本：

- 浏览器类工具：名字、参数、是否支持读取页面文本、是否支持截图
- 是否有登录态（本地浏览器已登录 / 云端会话 / 都没有）
- 客户端版本：宿主名称 + 版本号
- 本 Skill 版本：`python job-fit-assistant/scripts/jfa.py --version`
- Python 版本与依赖：`python -m pip list | findstr /i "docx pymupdf pillow"`

把结果填进 `docs/host-verification-record.md`（模板见下）。

## 1. 受控测试页面

准备一个**你自己可控**的本地页面，避免真的在招聘平台上试错：

1. 用 `tests/acceptance/final/heldout_job_same_role.txt` 的内容做成一个静态 HTML，
   在本地起一个服务器（`python -m http.server 8000`），页面标题写"质量效能工程师 · 锦城智能科技"。
2. 再做第二个页面，内容换成 `heldout_job_growth.txt`（公司同为锦城，职位不同）。
3. 两页 URL 分别记为 `P1`、`P2`。

## 2. 逐项验证（每项都要留证据）

| # | 场景 | 操作 | 预期 | 证据 |
|---|---|---|---|---|
| H1 | 正常读取 | 打开 P1，读取详情区域，`jfa job add --company 锦城智能科技有限公司 --title 质量效能工程师 --url P1 --job-ref test-1 --detail-region job-detail` | 成功，`identity.verified=true` | `jfa job show <id> --json` |
| H2 | 串页 | 打开 P1 后切到 P2，但用 P1 的职位名记录 | 退出码 4，拒绝写入 | 错误输出 |
| H3 | 串页-同公司不同职位 | 打开 P2，用 P1 的职位名记录 | 拒绝（职位不在页头） | 错误输出 |
| H4 | 用户覆盖 | 页面只用 LOGO 无公司名时，让**你自己**输入确认原话，Agent 用 `--override-statement "<你的原话>" --override-evidence "<URL+页面标题>"` | 成功，记录 `identity.override`，`job show` 显示⚠ | `job show --json` |
| H5 | 登录失效 | 退出登录后再读取 | 读取失败 → `job session --status paused --reason "登录失效"`，不重试 | session.json |
| H6 | 验证码 | 触发验证码 | 同上，暂停，不绕过 | session.json |
| H7 | 用户取消 | 读取到一半让你停止 | Agent 停止并保存已读部分，不继续导航 | 会话日志 |
| H8 | 读取上限 | 连续记录 9 个岗位（`--index 9`） | 退出码 7（`E_PAUSED`），不继续采集 | 错误输出 |
| H9 | 不误触发送 | 全程观察浏览器是否出现"打招呼/投递/上传"动作 | 不出现；工具只读 | 截图 / 页面状态 |
| H10 | 不外发 | 用抓包工具（Fiddler/mitmproxy）或系统防火墙日志观察 | 只有浏览器自身对目标的请求；本工具进程无出站连接 | 抓包截图 |

**H10 才是"不会外发"的充分证据**；代码里没有 HTTP 客户端只是必要条件。

## 3. 真实 BOSS（或同类平台）测试的前置条件

只有在同时满足以下条件时才做：

1. 你有该平台的账号，且**自己**登录；
2. 平台服务条款允许自动化/辅助工具读取公开职位信息；
3. 只读约定范围：职位详情页的标题、公司、地点、职责、要求、薪资；
4. **不发送**打招呼、**不投递**、**不修改**在线简历；
5. 单次会话读取数量 ≤ 8，遇到风控立即停止。

不满足任一条，就不要在真实平台上跑。用第 1 节的本地页面即可验证同样的逻辑。
