# 导出与校验

## 1. 产物清单

一次 `jfa export <job_id>` 产出 9 个文件 + 一个校验记录：

| 产物 | 文件名后缀 | 说明 |
| --- | --- | --- |
| DOCX | `.docx` | 主交付，单栏中文模板 |
| PDF | `.pdf` | 文字可选中、可搜索 |
| 纯文本 | `.txt` | 便于复制、搜索、二次检查 |
| 修改对照 | `-修改对照.md` | 逐条 before/after/理由/要求/事实/状态 |
| 匹配与缺口 | `-匹配与缺口.md` | 覆盖率、逐条结论、缺口、注意事项 |
| 事实与待确认 | `-事实与待确认.md` | 状态统计、未确认、冲突、年限口径 |
| 打招呼草稿 | `-打招呼草稿.md` | 草稿，不会自动发送 |
| 文档模型 | `-resume-doc.json` | 导出的唯一内容来源，可复查 |
| 渲染页 | `-pages/page-NN.png` | 逐页截图，用于人工复核 |
| 清单 | `manifest.json` | 所有产物 + sha256 + 校验结论 |

## 2. 命名与版本

```
<公司>-<职位>-v<N>-<YYYYMMDD-HHMMSS>.<ext>
```

- 公司/职位做安全化处理：去掉 `\/:*?"<>|`、控制字符，空格转 `-`，保留中文，最长 24/28 字符，避开 Windows 保留名（CON、NUL、COM1…）。
- `v<N>` 来自改写方案版本。
- 时间戳精确到秒。**任何情况下都不覆盖已有文件**：同名会追加 `-2`、`-3`。
- 再次导出到同一 `out/<jid>/vN/` 时，文件名不同，旧文件保留。

## 3. 排版底线

| 规则 | 值 |
| --- | --- |
| 页面 | A4，页边距 1.5/1.7 cm |
| 正文字号 | ≥ 9.5pt（硬下限） |
| 排版 | 单栏、无分栏、无嵌套表格 |
| 照片 | 默认关闭，`--photo` + 样式里 `photo.enabled` 才出现 |

**不允许用缩小字号把两页压成一页。** 实现方式：导出时按 10pt → 9.5pt 依次试排（最多 4 次），到 9.5pt 还超过 `max_pages` 就接受多页并在结果里说明。低于 `min_font_pt` 直接报错拒绝。

## 4. PDF 后端链

```
libreoffice → word → builtin
```

| 后端 | 前提 | 特点 |
| --- | --- | --- |
| `libreoffice` | 装有 soffice | 版式最接近 Word，跨平台 |
| `word` | Windows + Word + pywin32 | 与 DOCX 完全一致；**在子进程中执行并带超时**，避免 Word 弹窗把整个流程卡死 |
| `builtin` | 只需 PyMuPDF | 从同一文档模型直接排 PDF，永远可用；版式与 Word 不完全一致 |

`builtin` 的取舍写在报告里：宁可交付一份版式略有差异但内容可核验的 PDF，也不要交一个空文件或干脆失败。字体优先嵌入系统中文字体（YaHei / PingFang / Noto），找不到才退回 PyMuPDF 内置字体（此时 Latin 会偏全角，报告里会提示）。

三个都不可用 → `E_EXPORT`，明确指出失败原因，并且**不留下 0 字节 .pdf**。

## 5. 导出后校验（自动执行）

| 检查 | 判定 | 不通过意味着 |
| --- | --- | --- |
| DOCX 可重新读取 | 能打开并提取文本 | 文件损坏 |
| DOCX 内容完整 | 期望的每一段都能在 DOCX 找到（松散匹配，忽略分隔符差异） | 写入丢失 |
| PDF 已生成 | 存在且 > 1KB | 空文件 |
| PDF 页数 | ≤ `max_pages`，否则警告 | 内容偏多 |
| 空白页 | 页面墨水占比 < 0.15% | 分页错误 |
| 乱码 | 无 U+FFFD / 豆腐块 | 字体缺失或编码问题 |
| 溢出与截断 | 所有文字 bbox 在可打印区域内 | 文字被页面裁掉 |
| 重叠 | 行框重叠面积比 < 30% | 排版错乱 |
| 字号下限 | 正文最小字号 ≥ 9.5pt（页脚页码不计） | 被强行压缩 |
| 文字遗漏 | 期望行在 PDF 中可定位比例 ≥ 90% | 有内容没排进去 |
| 分页文字 | 多页时每页都有文字 | 有空白页 |
| DOCX/PDF 一致 | 字符覆盖率 ≥ 97% | 两个文件内容不同 |
| 文字可选中 | PDF 可提取 > 50 字 | 变成了图片 |

校验结果写进 `-校验结果.json` 与 `manifest.json`。

- 有 `fail` → 退出码 5，逐条列出。
- 只有 `warn` → 退出码 0，但在报告里保留警告。
- **校验不通过时不要口头说"导出成功"。**

## 6. 常见校验失败与处理

| 失败项 | 常见原因 | 处理 |
| --- | --- | --- |
| `pdf_overflow` | 字体度量与实际绘制不一致 | 已内置 2% 余量；仍失败说明该后端度量异常，换后端 |
| `pdf_line_coverage` | 内容被裁掉 / 分页吞行 | 看 `missing` 字段定位是哪几行，缩小内容或换后端 |
| `docx_pdf_consistency` | 后端渲染漏段 | 换后端重试；仍失败则报告"PDF 不可信" |
| `pdf_blank_pages` | 强制分页或空段落 | 检查是否有多余分页符 |
| `pdf_font_floor` | 样式里 `min_body_pt` 被改小 | 改回 ≥ 9.5 |

## 7. 交付话术

导出一份诚实的结果，需要同时说清四件事：

1. **交付了什么**：DOCX/PDF/TXT + 四份报告，路径。
2. **怎么校验的**：重抽取、逐页渲染、DOCX/PDF 一致性，结论。
3. **不完整在哪**：职位详情是否完整、必备覆盖率、多少条待确认未写入。
4. **没有做什么**：没有投递、没有发送、没有改在线简历。

示例：

> 已生成 v1：DOCX 37KB / PDF 2 页 / TXT。校验 13 项全部通过（含逐页渲染与 DOCX-PDF 一致）。
> 注意：该岗位"加分项"未读到，必备条件覆盖率 60%，另有 2 条待确认内容未写入简历。
> 打招呼只给了草稿，没有发送；在线简历未改动。
