# 筛选：硬条件、软偏好、薪资

## 1. 顺序不可颠倒

```
硬条件（可判定为不合格） → 软偏好（只排序） → 薪资比较（单独结论）
```

先跑软偏好会让人用"感觉不错"掩盖"根本不满足硬条件"。

## 2. 硬条件清单

| id | 条件 | pass | fail | unknown |
| --- | --- | --- | --- | --- |
| `city` | 期望城市 | 岗位地点命中 | 明确不在范围 | 用户没填 / 岗位没读到地点 |
| `work_mode` | 工作方式 | 命中 | 明确不符 | 岗位写"未说明" |
| `salary_floor` | 月基薪下限 | 保证年化 ≥ 下限×月数 | 保证年化更低 | 岗位面议/未写薪资 |
| `degree` | 学历上限 | 岗位要求 ≤ 用户学历 | 岗位要求更高 | 岗位没写学历 |
| `exclude_company` | 排除公司 | 不在列表 | 命中 | 用户没设 / 岗位没公司名 |
| `must_keyword` | 必备关键词 | 全部出现 | 有缺失 | 用户没设 |
| `exclude_keyword` | 排除关键词 | 未命中 | 命中 | 用户没设 |

## 3. 未知 ≠ 不符合

这是本工具最容易出错、也最必须守住的点。

- 任何 `unknown` 都不会让岗位变成 `ineligible`。
- 有 `unknown` 且至少有一项明确 `pass` → `conditional`（条件待确认）。
- 全是 `unknown` → `insufficient_info`（信息不足）。
- 只有出现 `fail` 才 `ineligible`。

报告里必须让用户看到"哪些条件我没法判断"，而不是给一个看似干脆的淘汰结论。

## 4. 薪资模型

薪资不是一个数字，是四件事：

| 维度 | 字段 | 说明 |
| --- | --- | --- |
| 固定底薪 | `min_monthly` / `max_monthly` | 保证部分的下限/上限 |
| 发薪月数 | `months_per_year` | 13/14 薪常见，超出 12 的部分通常与绩效挂钩 |
| 绩效/奖金 | `has_performance_pay` | 发放条件未知，不计入保证收入 |
| 提成/佣金 | `has_commission` | 比例未知，不计入保证收入 |

派生：

```
guaranteed_annual = min_monthly × months_per_year
possible_annual   = max_monthly × months_per_year
```

**13 薪以上的部分标 `months_conditional`**：写"20-30K·13薪"时，第 13 个月是条件性的，报告里要说明。

解析细节：

- 区间两侧只写一次单位（`20-30K`）时，单位套用到两侧。
- 年薪自动 ÷12 折算为月基薪，并注明"已折算"。
- 日薪按 21.75 个工作日/月折算。
- 未标月/年且数值 ≥ 10 万时，提示"可能把年薪误当月薪，需人工确认"。
- `面议` → `negotiable`，不做数字比较，也不判不合格。

## 5. 比较结论

| verdict | 条件 | 含义 |
| --- | --- | --- |
| `meets_target_guaranteed` | 保证下限 ≥ 目标年薪 | 按底薪就够 |
| `overlap_only` | 目标落在 [保证下限, 可能上限] 之间 | **仅区间相交** |
| `below_target` | 可能上限 < 目标 | 到不了 |
| `negotiable` / `no_data` | 面议 / 没写 | 无法比较 |
| `unknown` | 用户没给目标 | 只展示构成 |

`overlap_only` 必须带这句话：

> 薪资区间与期望区间相交，只说明该岗位在理论上有谈到的可能，不等于你能拿到目标数字：实际报价取决于面试评级、岗位预算与议价，提成/绩效/13 薪以上通常附带条件。

## 6. 软偏好评分

```
score = Σ(component_score × weight) / Σ(weight)
```

默认权重：`title_match 0.35` `skill_overlap 0.35` `salary_fit 0.20` `location_fit 0.10`。

- `title_match`：职位名与期望方向的 token 重叠度。
- `skill_overlap`：岗位术语与已确认事实术语的重叠（有事实档案时）；否则退化为偏好行业命中。
- `salary_fit`：达标 1.0 / 区间相交 0.55 / 低于目标 0.15 / 无法比较 0.5。
- `location_fit`：命中 1.0 / 不命中 0.0 / 信息不足 0.5。

信息不足时一律给中性分 0.5，**不用 0 分偷偷淘汰**。

软偏好只影响排序，报告里要写"软偏好只用于排序比较，不改变硬条件结论"。

## 7. 输出字段

`screen` 输出 `screening/latest.json`：

- `counts`：四类结论计数；
- `results[]`：每个岗位的硬条件明细、软分与分项、薪资比较、完整性、`caveats[]`；
- `policy`：口径声明（未知不淘汰、硬条件优先、区间相交不等于达标）。

`caveats` 会自动带上：区间相交提示、职位不完整提示、可能重复提示。
